## 1. Scope, method and evidence standard

Read the previous reports, `docs/jobhunter_autonomy_review/01_repository_map.md` and `docs/jobhunter_autonomy_review/02_search_execution_trace.md`, before extending their findings. Their local bytes match the published baseline. ### Evidence labels and status interpretation

- **S — verified by source inspection:** implementation/configuration/test definition read directly; not execution success.
- **T — executed existing test:** passed in this phase's full regression run using disposable data and fixture transports.
- **C — controlled execution:** additional synthetic source-reuse/registry checks described in Section 7.
- **H — historical recorded sample:** committed aggregate verification artifact dated 2026-10-29; not freshly reproduced, independently attested, or evidence of sustained availability.
- **I — inferred:** a consequence of the cited code relationships, not measured global recall.
- **U — unknown:** needs live access, production configuration, language/recall evaluation or a longer-running test.

Matrix statuses (verification scope is mandatory):

- **IV** — Implemented and verified **offline/fixture only**; not current live availability or autonomous discovery.
- **IU** — Implemented but not verified for the stated operational capability.
- **PI** — Partially implemented: narrower route or unavailable broader capability.
- **CA** — Configured but lacking a functional adapter.
- **IN** — Supported indirectly through another mechanism, such as ATS/feed/import.
- **AB** — Absent direct adapter in the inspected closed registry/scanners, not necessarily impossible externally.
- **NV** — Inaccessible or not verifiable live in this environment; distinct from offline implementation status.

**No source receives a fresh-live-verified designation in this audit.** IV and NV can coexist: the implementation was fixture-tested, while live access was not tested. No clear CA case was found: Monster/StepStone are directory mentions, not enabled targets; Google has an actual adapter, albeit historical failure evidence.

### Headline findings

1. **30 registry kinds are not 30 independent publishers.** Nine JobSpy providers and duplicate native/Scrapling publisher routes are included. Workday is a separate legacy scanner, not a registered kind. S/C: `jobhunter_app/sources.py:18–58,93–190`; `scanners/workday.py:64–105`.
2. **16 starter routes enable zero-input collection within a developer-chosen universe.** No new employer/site discovery implied. S/T: `jobhunter_app/automatic.py:17–39,54–85`.
3. **Reusable ATS collectors exist, autonomous ID discovery does not.** C verified new synthetic IDs for Greenhouse, Lever, Ashby and SmartRecruiters. `jobhunter_app/sources.py:111–139,193–261`.
4. **Primary Scrapling covers two fixed sites.** Optional Scrapling parsing on Wuzzuf/Naukrigulf is another narrow use, not a general discovery agent. S/T: `jobhunter_app/scrapling_engine.py:10–47`; `jobhunter_app/scrapling_parser.py:10–31`.
5. **Source management and finite query vocabulary remain the avoidable manual burden.** Directory search links are not executed. S/C: `config/portals.yml:133–195`; `scanners/jobspy_scanner.py:53–117`; `jobhunter_app/source_directory.py:26–34`.

## 3. What “configured” and “automatic” actually mean

- **Static application configuration:** `config/portals.yml` defines title/location filters, `tracked_companies`, primary queries and provider overrides. `jobhunter_app/expanded_sources.py:13–20,28–37` reads this file for dashboard JobSpy units. Changing the candidate profile does not edit it. S; prior Part 2 controlled profile-change check.
- **Runtime source registration:** `register(store,kind,identifier,approved) upserts a SQLite source's approval; `Source` validates its type and ID. It does not fetch a supplied homepage, identify the ATS, inspect a sitemap or discover other boards. `jobhunter_app/sources.py:93–148,255–261`; S/C.
- **Default selection:** `configure` seeds only `STARTERS`; it preserves existing paused/unapproved records. After setup, automatic scheduling considers **all approved registered due sources**, including manually added ATS/feed/social records if setup is complete—not only starters. Up to 10 attempts/cycle; readiness/cooldown/family gates still apply. `jobhunter_app/automatic.py:54–85,164–202`; S/T. Registering an approved new source while automatic mode is running can make it eligible later without an explicit manual scan.
- **UI/documentation mismatch:** `jobhunter_app/static/discovery.js:17` says “Nothing runs until you request a scan,” while the coordinator iterates all approved sources. `jobhunter_app/source_directory.py:9` still says “eight” JobSpy platforms although `SITES` contains nine, and directory rows often describe adapters as manual even though the scheduler can run them. These labels must not override runtime evidence. `jobhunter_app/source_directory.py:9,30–34`; `scanners/jobspy_registry.py:2`; S, C enumeration.
- **Two engine choices do not imply general routing intelligence:** `fetch` dispatches by already assigned kind; it does not automatically select API vs HTML vs JobSpy from a new website. Shared Jobicy/Arbeitnow cooldowns couple their native and HTML routes. `jobhunter_app/sources.py:156–190`; `jobhunter_app/source_health.py:8–14,40–48`; S/T. No automatic fallback is implied by two available adapters.

### The missing handoff

The existing reusable half is:

```text
known supported source + known identifier + approval/setup
    -> Source validation -> register -> approved/due automatic or manual scan
    -> existing bounded adapter -> canonical jobs or post triage
```

The missing general half is:

```text
candidate intent -> search/discovery leads -> first-party employer/source identity
    -> ATS/feed/platform identification -> access/capability validation
    -> proposed or permissible source registration -> feedback on useful new scope
```

This second diagram names **missing responsibilities**, not a proposed implemented architecture. `directory() stops at strings containing Google links; it neither calls a search service nor mutates a registry. C proved its output can be generated with network forbidden and no added source records. The parser/transport libraries cannot independently supply this missing discovery handoff. S/C evidence: `jobhunter_app/source_directory.py:26–34`; `jobhunter_app/sources.py:255–261`; `jobhunter_app/scrapling_engine.py:23–38`.
